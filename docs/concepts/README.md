## 架构概览

```text
+--------------------------------------------------------------------------+
|                               用户态                                      |
|                                                                          |
|  +------+ +-------+ +--------+ +---------+ +-----+ +------+ +----------+ |
|  | init | | ramfs | | diskfs | | console | | blk | | net  | | sh / 程序 | |
|  | 名字  | | 内存   | | 磁盘    | | 终端输入  | | 磁盘 | | 网卡+ | |          | |
|  | 服务  | | 文件   | | 文件    | | 服务     | | 驱动 | | 协议栈 | |          | |
|  +------+ +-------+ +--------+ +---------+ +-----+ +------+ +----------+ |
|     ^         ^         ^           ^         ^       ^          |       |
|     +---------+---------+-----------+---------+-------+----------+       |
|                  IPC 消息 + 共享内存（进程之间唯一的通信方式）               |
+--------------------------------------------------------------------------+
                                   | 系统调用
                                   v
+--------------------------------------------------------------------------+
|                               内核                                        |
|   任务与调度  |  地址空间 / COW  |  IPC  |  中断转发  |  调试串口输出       |
|   ----------------------------------------------------------------      |
|                    硬件抽象层 (HAL): i686 / x86_64 / arm64                |
+--------------------------------------------------------------------------+
                                   |
                                   v
+--------------------------------------------------------------------------+
|                     硬件：CPU、内存、中断控制器、时钟、设备                  |
+--------------------------------------------------------------------------+
```

内核里没有文件系统、网络和设备驱动（除了调试输出用的串口、x86 上的屏幕，和调度用的时钟）。驱动是用户进程，通过系统调用访问端口、映射设备内存、接收中断；每个驱动只碰得到 init 许可给它的那一个设备（见 [特权与硬件访问](../reference/hardware.md)）。

## 关键设计决策

### 1. 微内核

内核只负责 CPU/中断、内存、调度、系统调用和 IPC。其余功能是用户态的服务进程，彼此通过同步的消息传递协作，大块数据走共享内存。一个服务出错只影响它自己。

### 2. 高半核设计

内核映射在地址空间的高半部分（i686 上是 0x80000000 以上），用户空间占用低半部分。

### 3. Copy-on-Write (COW)

`fork()` 不复制内存，父子进程共享只读的物理页，写入时才复制。设备内存和进程间共享内存用单独的“共享页”标记，`fork` 之后仍然共享。

### 4. 抢占式多任务，内核不可抢占

时钟中断驱动时间片轮转，但只在返回用户态时切换任务；内核代码自己让出或阻塞。

### 5. 没有内核里的“文件”

内核不认识路径和文件描述符。`exec` 接受的是调用者内存里的一个 ELF 映像；文件服务是普通的用户进程。
