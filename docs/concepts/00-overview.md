## 架构概览

```
+--------------------------------------------------------------------------+
|                               用户态                                      |
|                                                                          |
|  +------+ +-------+ +--------+ +------+ +-----+ +------+ +-------------+ |
|  | init | | ramfs | | diskfs | | uart | | blk | | net  | | sh / 普通程序 | |
|  | 名字  | | 内存   | | 磁盘    | | 串口  | | 磁盘 | | 网卡+ | |             | |
|  | 服务  | | 文件   | | 文件    | | 驱动  | | 驱动 | | 协议栈 | |             | |
|  +------+ +-------+ +--------+ +------+ +-----+ +------+ +-------------+ |
|     ^         ^         ^         ^        ^       ^            |        |
|     +---------+---------+---------+--------+-------+------------+        |
|                  IPC 消息 + 共享内存（进程之间唯一的通信方式）               |
+--------------------------------------------------------------------------+
                                   | 系统调用
                                   v
+--------------------------------------------------------------------------+
|                               内核                                        |
|   任务与调度  |  地址空间 / COW  |  IPC  |  中断转发  |  调试串口输出       |
|   ----------------------------------------------------------------      |
|                    硬件抽象层 (HAL): i686 / x86_64 / arm64                |
+--------------------------------------------------------------------------+
                                   |
                                   v
+--------------------------------------------------------------------------+
|                     硬件：CPU、内存、中断控制器、时钟、设备                  |
+--------------------------------------------------------------------------+
```

内核里没有文件系统、网络和设备驱动（除了调试输出用的串口和调度用的时钟）。
驱动是带特权的用户进程，通过系统调用访问端口、映射设备内存、接收中断。

## 关键设计决策

### 1. 微内核

内核只负责 CPU/中断、内存、调度、系统调用和 IPC。其余功能是用户态的服务进程，
彼此通过同步的消息传递协作，大块数据走共享内存。一个服务出错只影响它自己。

### 2. 高半核设计

内核映射在地址空间的高半部分（i686 上是 0x80000000 以上），用户空间占用低半部分。

### 3. Copy-on-Write (COW)

`fork()` 不复制内存，父子进程共享只读的物理页，写入时才复制。设备内存和进程间
共享内存用单独的“共享页”标记，`fork` 之后仍然共享。

### 4. 抢占式多任务，内核不可抢占

时钟中断驱动时间片轮转，但只在返回用户态时切换任务；内核代码自己让出或阻塞。

### 5. 没有内核里的“文件”

内核不认识路径和文件描述符。`exec` 接受的是调用者内存里的一个 ELF 映像；
文件服务是普通的用户进程。

## 代码组织

```
src/
├── arch/           # 架构相关代码 (i686, x86_64, arm64)
├── kernel/         # 任务、调度、系统调用、IPC、中断转发、ELF 加载
│   ├── sync/       # 同步原语
│   └── syscalls/   # 进程和内存相关的系统调用实现
├── mm/             # 内存管理 (PMM, VMM, 堆)
├── drivers/        # 串口（调试输出）和时钟
├── lib/            # 内核库 (kprintf, klog, 字符串)
├── include/        # 头文件
└── tests/          # 内核测试 (KTEST=1)

user/
├── lib/            # 用户态库：系统调用包装、printf、名字/文件/块设备服务的客户端
├── init/           # 第一个进程：启动模块 + 名字服务
├── uart/ blk/ net/ # 用户态驱动（net 里还有协议栈）
├── ramfs/ diskfs/  # 文件服务
├── sh/             # 命令行
└── ...             # 放在启动映像里的程序
```
