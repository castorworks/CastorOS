# 特权与硬件访问

用户态驱动需要碰硬件，内核为此提供下面几样东西。谁能用由两样东西决定：进程的 `privileged` 标志，和它的许可表。各个驱动怎么用它们见 [用户态驱动](drivers.md)。

- **特权的来源**：内核直接创建的 init 有特权，`fork` 和 `exec` 都保留；进程调用 `drop_privilege()` 之后永久失去。有特权的进程什么硬件都能碰。系统里只有 init 留着特权：它启动每个模块之前都先让子进程放弃。
- **按设备授权**：每个进程有一张许可表，最多 8 条，每条是一段 I/O 端口（`HW_PORTS`）、一段设备内存（`HW_MEMORY`）或者几条中断线（`HW_IRQ`）。没有特权的进程只碰得到表里有的东西。表只能在还有特权时用 `hw_allow(kind, start, count)` 填，`fork` 和 `exec` 都保留，放弃特权之后不能再加，也没有办法交给别的进程。init 启动驱动的过程因此是：`fork`，在子进程里找到这个驱动的设备并 `hw_allow` 它占用的资源，`drop_privilege`，`exec`。驱动从第一条指令起就只碰得到自己的设备：串口驱动读不了磁盘的寄存器，磁盘驱动认领不了网卡的中断。
- **设备在哪里**：驱动不找设备，也不把地址写死。许可给它的就是它的设备：`hw_allowed(index, &range)` 读出许可表里的一条，用户库的 `hw_find(kind, n, &range)` 取某一种资源的第 n 条。找设备是 init 的事（`user/init/init.cpp` 里的 `allow_*` 函数）：x86 上串口的端口和中断是 PC 的固定值，virtio 设备靠扫 PCI 配置空间发现；arm64 上设备的位置是固件用设备树告诉内核的，init 用 `device_find(compatible, index, &info)` 按型号来查（如 `"virtio,mmio"`、`"arm,pl011"`；设备树里一个设备会列出几个型号，从最具体的到最一般的，按其中任何一个都查得到），得到寄存器的物理地址和中断号。`device_find` 只对特权进程开放。
- **I/O 端口**（仅 x86）：`io_read` / `io_write`，宽度 1/2/4 字节。许可是精确到端口的。许可给一个进程的端口，它可以直接用 `in` / `out` 指令访问，不用进内核：TSS 后面有一张 I/O 许可位图（每个端口一位，平时全部关着），调度器换一个用户任务上 CPU 时把它许可表里的端口打开，换下去时关上（`hal::Platform::set_user_ports`）。用户库的 `io_read` / `io_write` 先看端口在不在自己的许可表里：在就直接执行指令，不在才走系统调用（有特权的 init 在那里通过，其余的被拒绝）。绕过用户库直接碰没被许可的端口，CPU 产生一般保护异常，进程被终止。
- **设备内存**：`map_device(phys, len)` 把设备的寄存器或显存映射进调用者的地址空间（不缓存）。只接受设备地址区，也就是固件没有报告为可用内存的地址（x86 上是 Multiboot 内存映射里的空洞，arm64 上是设备树的内存节点之外）；普通内存一律拒绝，有特权也不行。映射同样带“共享”标记，`fork` 后父子都能访问设备。许可按页算：映射的最小单位是一页，许可了一页里的一部分就可以映射整页。
- **DMA 内存**：`dma_alloc(len, phys*)` 分配物理上连续、已清零的内存并映射进调用者，同时告知物理地址，供驱动把缓冲区交给设备。只给驱动，也就是有特权或者许可表不空的进程。
- **设备中断**：`irq_claim(irq)` 认领一条内核自己没在用、并且许可给了调用者的中断线（x86 是 PIC 的 IRQ 号，arm64 是 GIC 的 SPI 中断号）。中断到来时内核屏蔽这条线，并向属主投递一条 `sender == IPC_KERNEL`、`label == IPC_LABEL_IRQ`、`data[0] == irq` 的消息；属主没在 `recv` 时记为待处理，下一次 `recv(IPC_ANY)` 先收到它。驱动处理完设备后调用 `irq_ack(irq)` 重新打开中断线。进程退出时它的认领被释放。一条线可以被多个进程认领（x86 上磁盘和网卡就共用 IRQ 11）：中断到来时每个属主都收到消息，驱动要自己看设备状态、没有事就直接 `irq_ack`；所有属主都应答之后内核才重新打开这条线。
- **关机和重启**：`power(POWER_OFF)` 让机器断电，`power(POWER_REBOOT)` 让它复位、从固件重新启动。要特权，所以实际上只有 init 调用：内核不知道文件系统，调用了立刻就做，让磁盘上的内容先停稳是 init 的事（别的程序请 init 来做，见 [微内核结构](../microkernel.md) 的“关机和重启”）。成功就不返回；返回 -1 说明固件没有给出办法。怎么做因机器而异：
  - x86 关机靠 ACPI（`src/drivers/x86/acpi.cpp`）：FADT 这张表说电源管理的控制寄存器在哪个端口上，它指向的 DSDT 里 `\_S5` 这个名字给出要写进去的值；电源管理还在固件手里的话先让它交出来。
  - ACPI 的表在固件保留的内存里，不一定在内核的直接映射区里（i686 上内存超过 2GB 时就不在，而且内核半区已经被直接映射占满，没有空的地址可用）。这时内核借自己的一页数据所在的虚拟地址，临时改成指向要读的物理页，读完改回去，表的内容拷到堆上再解析。
  - x86 复位的办法有好几代，从新到旧一个个试（`src/drivers/x86/power.cpp`）：ACPI 的复位寄存器、键盘控制器的复位线、芯片组的 `0xCF9` 端口，都不行就清空中断描述符表再触发一个异常，CPU 处理不了只好复位。所以重启在 x86 上总能成。
  - arm64 上两样都是固件调用（PSCI 的 `SYSTEM_OFF` 和 `SYSTEM_RESET`），和启动其余的 CPU 用的是同一个接口；设备树里没有 PSCI 就做不了。

内核一侧的实现在 `src/kernel/hw_access.cpp`（许可表）、`src/kernel/user_irq.cpp`、`src/kernel/syscall.cpp` 和 `src/kernel/syscalls/mm.cpp`。

## 当前的限制

- 数量上的上限：`map_device` 一次最多映射 16MB，物理地址要页对齐；`dma_alloc` 一次最多 1MB；全系统同时最多 16 个中断认领，同一个进程不能把一条线认领两次。
- 许可拦不住能做 DMA 的设备。驱动把一个物理地址交给设备，设备就往那里读写，内核看不见也管不了（没有 IOMMU）。所以许可表防的是驱动的错误和越界，不是一个存心作恶的磁盘或网卡驱动。
- 设备内存的许可以页为单位。QEMU virt 上 virtio-mmio 的槽位每个只有 0x200 字节，一页里有 8 个，磁盘和网卡通常落在同一页：两个驱动互相映射得到对方的寄存器。
- 中断线是共享的（x86 上磁盘和网卡共用 IRQ 11）：得到同一条线的驱动都会收到对方设备的中断消息。
- 许可表是进程自己的，不能转交：一个驱动不能把它的设备再分给子进程里的一部分，子进程拿到的总是整张表。
- 关机不解释 ACPI 的字节码（AML），只在 DSDT 里找 `_S5` 最常见的写法（一个包，前两项是小整数），也不执行固件要求在睡眠之前调用的方法（`_PTS`）；只看 DSDT，不看 SSDT；只认 RSDT，不认 64 位的 XSDT。QEMU 和多数 PC 上够用，不够用的机器上 `power` 返回 -1。没有电源键的处理：按电源键不会让系统关机。
- 有特权的进程（init）访问端口仍然每次一个系统调用：它能碰所有端口，要直接访问就得把整张位图打开。它只在启动驱动时扫一遍 PCI，不值得。
