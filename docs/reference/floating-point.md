# 浮点数

用户程序可以用浮点数和 SIMD 指令：`float`、`double` 照常写，`printf` / `snprintf` 认识 `%f`（`%.2f`、`%8.3f`；默认 6 位小数，最多 15 位）。

内核自己不用浮点/SIMD 寄存器，编译时就禁掉了（x86_64 的 `-mno-sse`，arm64 的 `-mgeneral-regs-only`；i686 的内核里没有浮点运算）。所以系统调用和中断进出内核时不保存它们，只在换一个用户任务上 CPU 时换：`Scheduler::schedule()` 把换下去的用户任务的寄存器存进它 PCB 里的 `fp_state`，把换上来的装回去（`hal::UserContext::fp_save` / `fp_restore`）。每次切换都换，不等到任务真的用了浮点指令再说：省掉一种异常的处理，代价是每次切换多读写几百字节。

| 架构 | 保存的内容 | 用的指令 |
|------|------------|----------|
| i686、x86_64 | x87、MMX、XMM0-7（x86_64 是 XMM0-15）、MXCSR，共 512 字节 | `FXSAVE` / `FXRSTOR` |
| arm64 | V0-V31、FPSR、FPCR，共 528 字节 | `src/arch/arm64/task/fp.S` |

用户库有一组数学函数（`math.h`）：`fabs`、`floor`、`ceil`、`fmod`、`sqrt`、`pow`、`exp`、`log`、`sin`、`cos`、`tan`。它们全部用普通的浮点运算写成（把参数化到一个小范围里，再用级数或牛顿迭代），不用 CPU 的专用指令，三个架构用的是同一份代码（i686 上编译器用 x87 做运算，中间结果的精度更高，最后一位可能和另外两个架构不同）；相对误差大约 1e-14，不是逐位正确舍入的，三角函数的参数很大（超过 1e9）时会损失精度。

`fork` 出来的子进程得到父进程此刻的浮点状态；`exec` 之后新程序从干净的状态开始（寄存器清空，所有浮点异常屏蔽）。

当前的限制：不保存 AVX 的高半部分（YMM/ZMM），内核也没有打开它们，用户程序不能用 AVX；i686 上 CPU 必须有 `FXSAVE` 和 SSE，没有就在启动时停下；`%f` 只有小数形式，没有 `%e` 和 `%g`，四舍五入是加半个末位再截断，正好落在中间的值可能和别的系统差一个末位。
