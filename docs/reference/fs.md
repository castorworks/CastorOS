# 文件服务

文件服务的协议和客户端接口在 `user/lib`（`fs.h`）。有两个实现同一套协议的服务，客户端库按文件名的前缀选择：

- 没有前缀 → `user/ramfs`（登记为 `"fs"`）：内容放在服务自己 `mmap` 来的内存里，开机时从启动映像装载，之后的改动重启即丢失。
- `disk:` 前缀 → `user/diskfs`（登记为 `"diskfs"`）：内容经[块设备服务](drivers.md#块设备blk)落在磁盘上，跨重启保留。

协议的服务端部分（句柄、请求分发，以及目录的规则）是公共的，在 `user/lib` 的 `fs_server` 里；每个客户的共享缓冲区和它的回收在 `clients` 里（`clients.h`，块设备和网络服务也用它）；一个文件系统只需要提供一组按文件号操作的函数（`struct fs_backend`）再调用 `fs_serve`。

## 路径和目录

文件用路径来指，各段之间用 `/` 隔开，整条路径（算成从根写起的样子）最长 63 个字符：

| 写法 | 意思 |
|------|------|
| `disk:a/b`、`ram:a/b` | 从磁盘 / 内存文件系统的根写起 |
| `/a/b` | 从当前目录所在的那个文件系统的根写起 |
| `a/b` | 从当前目录写起；`.` 是所在的目录，`..` 是上一级 |

**当前目录**是每个进程自己的，一开始是内存文件系统的根。`fs_chdir(path)` 换目录（那里得是一个存在的目录），`fs_getcwd` 读出来。命令行的 `cd` 和 `pwd` 就是这两个函数；它启动程序时把自己的当前目录交给程序（和标准输入输出的设置一起，见 [启动映像和命令行](shell.md)），所以程序从命令行所在的目录开始。

当前目录、`.`、`..` 都是客户端库（`user/lib/src/fs.cpp`）的事：它把调用者给的路径算成“哪个文件系统 + 从根写起的完整路径”再发给服务。服务不知道有当前目录这回事，它收到的永远是完整的路径；收到带 `.`、`..` 或者空段的路径一律拒绝。

目录要用 `fs_mkdir` 明确地建，文件只能建在已经存在的目录里（根目录总是存在），目录空了才能删（`fs_unlink`），目录不能当文件打开。`fs_list(dir, index, ...)` 列出一个目录的直接成员，告诉调用者每一项的名字、大小、是不是目录。`fs_rename(from, to)` 改名或者移到别的目录，目录连同里面的东西一起走；新路径上已经有东西、它的上一级不存在、把目录移进它自己、或者两个路径不在同一个文件系统里时失败。

这些规则只写了一遍，在 `fs_server` 里。后端看到的仍然是一张平的表：每一项有一个完整的路径、一个“是不是目录”的标志、内容。“`docs` 里有什么”就是“表里哪些项的路径以 `docs/` 开头、后面不再有 `/`”。这样两个文件系统的存储格式几乎不用变（diskfs 的目录表项里多用了一个保留字段当标志位，旧的磁盘映像照样能用，里面的文件都在根目录），代价是列一个目录要扫整张表。启动映像里的子目录（`user/bootfs/docs`）装载出来也是目录。

## 协议

- **连接**：客户第一次调用 `fs_*` 时 `mmap` 一块 4KB 缓冲区并 `mem_grant` 给服务；服务从授予通知里得知缓冲区的位置，按客户的 PID 记下来。
- **请求**：`FS_OPEN` / `FS_CLOSE` / `FS_READ` / `FS_WRITE` / `FS_SIZE` / `FS_UNLINK` / `FS_LIST` / `FS_MKDIR` / `FS_RENAME`。消息里只有参数（句柄、偏移、长度），路径和数据都在共享缓冲区里；读写带显式偏移，服务端不记文件位置。超过 4KB 的读写由客户端库拆成多个请求。
- **句柄**属于打开它的进程，别的进程用不了；`fork` 出来的子进程要自己重新连接（库会自动处理）。
- **回收**：服务用 `kill(pid, 0)` 探测客户是否还在，新客户连接时顺便清掉已退出客户的缓冲区和句柄。

- **服务重启**：服务进程不在了（崩溃后 init 会重启它），客户端库的下一个请求失败，同时忘掉这条连接；再下一个请求重新按名字找到新的服务。原来打开的句柄在新的服务那里不存在；ramfs 重启后只剩启动映像里的内容。

当前的限制：不能跨文件系统改名（用 `cp` 再 `rm`）；改名一个目录要逐项改它里面每一项的路径，中途失败会留下改了一半的结果；没有权限和时间戳；列目录要扫整张表；每个服务最多 16 个客户、64 个打开的句柄；已退出客户的资源要等下一个新客户连接时才回收。ramfs 里文件和目录合起来最多 128 个，每个文件最大 4MB。删除一个文件时，所有指向它的句柄（包括别的客户的）一并失效。

## diskfs 的磁盘格式

块大小 4096 字节：块 0 是超级块，之后是 FAT（每个块一个 32 位表项，记录文件的块链），再之后是 2 块目录表（定长 128 字节表项，每一项是一个文件或一个目录，名字是完整的路径；文件和目录合起来最多 64 个），其余是数据块。FAT 和目录在内存里各有一份完整副本，每次修改立刻把涉及的块写回磁盘，没有延迟写，所以不需要 `sync`。磁盘上没有有效的超级块时，只有空白的盘（块 0 全是 0）才自动格式化；盘上是别的东西——真机的硬盘上多半是另一个系统——`diskfs` 不动它，打印一行说明后退出，`disk:` 就用不了。要把这样一块盘交给 `diskfs`：运行 `disk erase`（要求敲 `erase` 确认，把块 0 清零），然后重启。超级块里记的大小和磁盘现在的大小对不上也算无效，所以同一份映像换一个大小挂上来同样要先 `disk erase`。开机自检遵守同一条规矩：不是空盘也不是 `diskfs` 的盘，它只读不写。

最近用过的 16 个数据块留在内存里（缓存），再读时不用去找块设备驱动。写是 write-through：同时写磁盘和缓存，磁盘上的内容从不落后，所以仍然不需要 `sync`。FAT 和目录本来就整个在内存里，不进缓存。

当前的限制：缓存只有 16 块（64KB），没有预读；绕过文件系统直接写磁盘扇区（`disk` 程序）的话缓存不会知道；没有日志，断电时正在进行的操作可能泄漏几个块（不会损坏其他文件）；最多管理 1GB；不认分区表，文件系统从磁盘的第 0 个扇区开始，所以不能和别的系统共用一块盘。
