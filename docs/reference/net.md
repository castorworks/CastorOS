# 网络

网络的协议和客户端接口在 `user/lib`（`net.h`），服务进程以 `"net"` 登记。服务的代码在 `user/net`，按层分成几个文件，彼此之间的接口都在 `net_internal.h`：

| 文件 | 内容 |
|------|------|
| `net.cpp` | 服务本身：地址配置、主循环（等中断、定时器、客户请求）、把请求分给各个协议 |
| `nic.cpp` | 网卡：打开许可给本进程的那一块，收发以太网帧。具体的设备在它下面，各一个文件（接口在 `nic.h`） |
| `virtio_net.cpp` | virtio-net 网卡，QEMU 里默认用的 |
| `e1000.cpp` | Intel 千兆网卡（82540 一族），只有 x86 |
| `ip.cpp` | 以太网、ARP、IPv4、回环、ICMP 回显 |
| `udp.cpp` | UDP 套接字和 `NET_UDP_*` 请求 |
| `tcp.cpp` | TCP 和 `NET_TCP_*` 请求 |
| `dhcp.cpp` | DHCP 客户端 |

## 客户端接口

- `net_info`：本机的 MAC、IP、掩码、网关、DNS 服务器，以及地址是否来自 DHCP。IP 为 0 表示还在配置。
- `net_ping(ip, timeout, &rtt)`：发一个 ICMP 回显请求，阻塞到收到应答或超时。
- `net_udp_open` / `net_udp_send` / `net_udp_recv` / `net_udp_close`：UDP 套接字。`recv` 带超时；数据经共享缓冲区传递。
- `net_tcp_connect` / `net_tcp_send` / `net_tcp_recv` / `net_tcp_close`：TCP 连接。`connect` 和 `recv` 带超时；`recv` 返回 0 表示对方已关闭。
- `net_tcp_listen` / `net_tcp_accept`：在一个端口上监听，接受连进来的连接（之后同样用 send / recv / close）。
- `net_resolve(name, &ip)`：把主机名解析成地址（库里用 UDP 向配置的 DNS 服务器发一个 A 记录查询）。

## 服务的结构

`user/net` 把网卡驱动和协议栈放在同一个进程里：主循环用一个 `ipc_recv(IPC_ANY)` 同时等网卡中断、定时器和客户请求，收到的帧直接交给协议栈，不需要在驱动和协议栈两个进程之间再传一次。阻塞的请求（ping、recv）不立刻应答，等回显或数据报到了、或者定时器发现它超时了再 `ipc_reply`。

## 协议栈

协议栈包括以太网、ARP（8 个表项，每 500ms 问一次，问 3 次没有回答就放弃并丢掉挂着的包；地址解析期间发往那个地址的包先挂起来，所有地址合起来最多挂 8 个，解析完成后按原来的顺序发出）、IPv4、ICMP 回显（也应答别人的 ping）、UDP、TCP。一个帧放不下的 IP 包分片发出；收到的分片按（源、目的、协议、标识）攒起来，拼齐了才交给上层。

发给自己地址的包不经过网卡：它们进一个回环队列（16 个包，满了就丢），回到主循环后再当作收到的包处理（不在发送的中途递归处理，否则会重入发送方还没更新完的状态）。

## 地址配置

服务启动时用 DHCP 获取地址、掩码、网关和 DNS 服务器：DISCOVER → OFFER → REQUEST → ACK，每 500ms 重发一次。DHCP 客户端在服务内部，直接用协议栈收发（这时还没有地址：只能发广播；收的时候来者不拒，因为服务器的应答可能直接发到将要分给我们的那个地址），所以不需要一个“配置地址”的对外接口。每个阶段重发 6 次，也就是 3 秒没有应答（等 OFFER 和等 ACK 各算各的）就退回 QEMU 用户网络的固定配置（10.0.2.15/24，网关 10.0.2.2，DNS 10.0.2.3）。配置完成之前 `net_info` 报告的 IP 是 0，ping 和 UDP 发送会失败。

地址是租来的：租期过半时向给地址的那台服务器发一个 REQUEST 续租（已经有地址，不用广播），收到 ACK 租期重新算；服务器不理就每 10 秒再问一次；到租期的 7/8 还没续上，改成广播，任何一台服务器答应都行（rebinding）；到租期满了还没续上、或者服务器明确拒绝，就放掉地址从头再来。没有别的事要等的时候，主循环把定时器设到该续租的时刻。

## TCP

TCP（`user/net/tcp.cpp`）是一个刻意保持简单的实现：

- 发送：每条连接一个 8KB 的环形缓冲区，放着还没被确认的数据。能发多少由对方通告的窗口决定；超时没被确认就从最早未确认处重发，超时时间每次翻倍（300ms 起，最多 4 秒），重试 8 次后放弃连接。对方窗口为 0 时发 1 字节探测。
- 接收：只接受按序到达的数据，放进 8KB 的环形缓冲区，通告窗口就是剩余空间；乱序的段丢掉并重复确认，靠对方重传。
- 关闭：`close` 之后已经交出去的数据仍会发完，再发 FIN，四次挥手在后台完成；支持对方先关、双方同时关。被复位或重试耗尽的连接，等着的请求都以失败返回。
- 监听：监听端口上收到 SYN 就建一条半开的连接并回 SYN+ACK，握手完成后排队等 `accept`。每个监听最多积压 4 条，半开的也算在内；满了之后新来的 SYN 不回应，等对方重发。握手完成之后、`accept` 之前到的数据照常进接收缓冲区。关掉监听时还没被接受的连接一并复位。
- 没有拥塞控制、选择确认、窗口缩放、延迟确认，没有 TIME_WAIT。

## 调试请求

有几条路径平时走不到，服务为自检留了四个调试请求。它们没有访问控制，任何进程都能调用。

- `NET_DEBUG_FRAGMENT`：让服务把每个包切得更小，用来验证分片和重组。
- `NET_DEBUG_RENEW`：让它立刻续租，用来验证 DHCP 续租。
- `NET_DEBUG_EXIT`：让它应答之后立刻退出，像崩溃了一样，用来验证 init 会重启它、客户端库会重新连上。
- `NET_DEBUG_DROP`（`net_debug_drop(tx, rx)`）：丢掉接下来发出的 tx 个、收到的 rx 个 TCP 帧，并返回至今的重传次数。发出方向只算带 SYN 或数据的帧：纯确认随时可能冒出一个（比如确认上一个连接迟到的 FIN），如果它也占名额，想丢的那个 SYN 就照常发出去了，测试会偶尔失败。

## 在 QEMU 里使用

`make run` 和 `make test` 都给 QEMU 挂一块接用户网络的 virtio-net 网卡，并用 `guestfwd` 把 10.0.2.100:7 接到宿主机的 `cat` 上，得到一个不依赖外网的 TCP 回显服务（自检用它）。

工具有 `ifconfig`、`ping <ip> [count]`（默认发 3 个）、`dns <name>`、`http <host> [path]`（对 80 端口做一次 GET，打印应答的开头）和 `echod [port] [connections]`（TCP 回显服务）。`dns` 和 `http` 要经 QEMU 的转发器访问外网，能不能成取决于宿主机能否上网。

要从宿主机连进来，给 QEMU 的用户网络加端口转发，例如 `-netdev user,id=net0,hostfwd=tcp:127.0.0.1:8007-:7`，在命令行里运行 `echod`，然后在宿主机上 `nc 127.0.0.1 8007`。`make run` 默认不加转发（会占用宿主机的端口）。

## Intel 千兆网卡

老 PC 上常见的有线网卡。init 找不到 virtio 网卡时，在 PCI 上的以太网卡里按厂商号和设备号找 82540 一族（QEMU 模拟的 82540EM，和笔记本上的 82540EP 等几个变种），打开它的设备内存访问和总线主控，把寄存器（一段设备内存）和中断线许可给 `net`。`net` 看许可表的样子决定用哪个驱动：virtio-net 在 x86 上是一段端口，这种网卡是一段设备内存。

驱动和网卡共用几块 `dma_alloc` 来的内存，靠寄存器告诉对方“我放到哪儿了”。收和发各有一个环：一排 16 字节的描述符，每个指着一个 2KB 的缓冲区；每个环有头、尾两个寄存器，头由网卡推进，尾由驱动推进，头尾之间的描述符归网卡。

- **收**：32 个缓冲区都交给网卡。网卡收到一帧就填进头上的缓冲区、在描述符上打上“完成”并发中断；驱动把帧交给协议栈，再把描述符还回去。
- **发**：把帧拷进尾上的缓冲区，推进尾。16 个描述符都还没发完时新的帧丢掉，和 virtio 的做法一样（TCP 会重传）。
- **启动**：复位网卡，读出 MAC 地址（复位后网卡自己装进地址寄存器；没有的话到它的小存储器里读），让链路起来，最多等 3 秒。等不到（没插网线）也照样就绪，之后插上网线网卡自己会接通。

`make run NET=e1000` 和 `make test NET=e1000` 把 QEMU 的网卡换成它。

当前的限制：只认 82540 一族的几个设备号，别的 Intel 千兆网卡（82541、82547、82573 以及更新的）和百兆的 Intel PRO/100 不认；不做校验和卸载、巨型帧和 VLAN；不收组播；链路断开或恢复时不通知协议栈（地址和 ARP 表照旧留着）；只在 QEMU 里验证过。

## 当前的限制

重组后的 IP 包最多 8192 字节，同时只能拼两个包，第三个包的分片到来时挤掉较早的那个；拼不齐的包超过 10 秒作废，但只在下一个分片到来时才检查；UDP 数据报仍然最多 1472 字节，所以往外发的包正常情况下不会被分片；TCP 连接和监听合计最多 8 个，8 个 UDP 套接字（每个最多积压 4 个数据报）、8 个同时进行的 ping；只支持 virtio 的 legacy 接口。
